WHY THIS EXISTS
#76 is merged: the flag derives on every read and the row chips render. Re-reading the running surface
(rule 12) on the merged tree found one acceptance item still unmet. The design doc's copy rule says:

  "Never a bare negative day count. `Start: 2026-10-06 · -1 d` is what the built roll-up prints for the
   started case today ... P2-5's acceptance includes: no surface prints a negative `days_to_start`."
  (design-concepts/LAYER2-PREBOARDING-UI.md, measured 2026-10-07 on origin/main, §5.1)

P2-5's own flag block rendered its negative safely (Math.abs + ago/to go, App.tsx:1629-1631). The row
renderer, App.tsx:1596, printed `{row.days_to_start} d` with no guard — so the two oldest surfaces (the
case list and the HR roll-up, which share that row) still showed a negative number. One place, one fix:
a single `relDays()` helper, so a third surface cannot drift from it later.
