ERRATUM — the P3-1 evidence pack, corrected in place
======================================================

Two defects in this pack, found by the lead and confirmed here by measurement. **Nothing is swapped or
deleted**: the files that carry them are delivered as they were, stay in manifest.txt, and this note is
what a reader is meant to hit. Rule: recording a stale premise beats editing it away.

1. THE MERGE-RESULT TREE IN `rig-run.txt` IS THE WRONG TREE, AND IT NAMED ITS OWN REVISION.
   The rig printed "merge result tree: ba6f5331…" and "MERGE RESULT == AFTER TREE: yes". Measured now:
     * `ba6f533124ef1ffeb249da379ed4e9ec98be0963`  = `1ef9e9c^{tree}` — the CODE commit the rig was run against.
     * `5951de62393f782f12986b7dd68a38a49f9c7a05`  = `f4314d8^{tree}` — the FINAL merge result (the merge of 93de0bd + 07c0b4b).
     * `5951de62393f782f12986b7dd68a38a49f9c7a05`  = `07c0b4b^{tree}` — this pack's own branch tip, which equals the merge result.
   The rig ran before the pack commit (77ac4ae) and the manifest-fix commit (07c0b4b) existed, so its
   statement was true of the revision it NAMED — its own transcript says `after=1ef9e9c` — and false as a
   claim about what merged. I then quoted `ba6f5331…` as "the merge result" in my report and PR, which is
   the defect: **a merge-result tree must be re-measured after the last commit that will merge; a tree
   digest taken at an earlier revision is a claim about that revision only.**
   Correction: the merge result is `5951de62393f782f12986b7dd68a38a49f9c7a05` at `f4314d8`.

2. `tsc-b.log` IS EMPTY (0 bytes), SO IT CANNOT REDDEN.
   Measured: `stat -c %s tsc-b.log` = 0. An empty file verifies happily against `md5sum -c`, so
   this artifact could never fail — it is a vacuous build proof, the class this team has paid for before
   ("a check that cannot redden proves nothing"). It is empty for a reason worth knowing: `npm run build`
   is `tsc -b && vite build`, and **`tsc -b` prints nothing when it succeeds**, so a log of it is empty by
   construction. The load-bearing half of the build proof is `vite-build.log` (it names the two dist
   assets) plus the exit codes, and the movement's own `build.log` — filed in
   `docs/evidence/movement-2026-10-22-1247/` — shows `> tsc -b && vite build` followed by vite's output
   with no tsc error, i.e. tsc exited 0.
   What a future pack must do instead: capture the exit code INTO the artifact, e.g.
   `( cd client && npx tsc -b --force > tsc-b.log 2>&1; echo "tsc -b exit $?" >> tsc-b.log )`, so the
   file has content that can be wrong.

THE DIGESTS IN `manifest.txt` still verify — they are digests of these delivered bytes, and they were
never in doubt. What was wrong was what I CLAIMED the bytes proved.
