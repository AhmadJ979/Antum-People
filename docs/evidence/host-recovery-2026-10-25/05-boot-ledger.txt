# host without trusting the wall clock. Read the two events SEPARATELY; do not collapse them:

#   2. A SUSPENSION (frozen and resumed):     boot_id UNCHANGED, uptime ADVANCES MORE SLOWLY than the
#                                             wall interval between the two lines. boot_wall (= date -
#                                             uptime) therefore moves FORWARD without any boot: it is
#                                             a derivation, not an instant. Never read it as a
#                                             boot time; its drift is the suspended time.
#   3. STILL RUNNING:                         boot_id unchanged and uptime advanced by the whole wall
#                                             interval; the guard's and product's ages advance with it.
