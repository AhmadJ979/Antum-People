### The defect in my own first fix, recorded rather than quietly regenerated

The first cut ran git with `-C <this file's own directory>`. `git ls-tree <rev> design-concepts`
reads its pathspec **relative to the directory git is told to work in**, and the file lives four
levels down, so it matched nothing and the run printed `0 ok, 0 FAILING, 0 unchecked`, **exit 0** —
a green over an empty document list, on a tree whose citations it had just failed to read. The
fix: git runs `-C <repository root>`, and an empty document list is ITSELF a refusal (exit 2).
Both are in the file's docstring, with the reason.

## 5. Two traps this file is written around, both measured here

1. **A copy is judged by ITS OWN script.** Running this repository's `check-all.py` with `cwd`
   set to the copy makes it judge the REAL tree (its root comes from its own `__file__`) and
   report it green while the doctored copy is never read. The copy's own script must be run — the
   assertion that caught it is the one demanding the run name the tree it judged.
2. **A non-git copy legitimately reddens two checks.** `check-index-ids.py`'s own docstring
   documents its blind spot: ids that resolve as git objects in the repository do not resolve in a
   copy (exit 1, "the CHECKER'S OWN BLIND SPOT"). So the gate narrows to one check with `--only`
   rather than reading a copy's whole verdict as if it were the tree's.

  and moving an instrument to tidy it would rename evidence.
- **`server/node_modules` is not ignored by `.gitignore`** (`git check-ignore` says no: the pattern
  is `node_modules/`, which matches directories and not a symlink). The operator step this change
  documents — `ln -s ... server/node_modules` — therefore leaves an untracked symlink that
  `git add -A` WOULD commit. One line (`node_modules` without the trailing slash) would close it.
  Not changed here: it is not this task's delta, and the entry point's own header reports untracked
  paths separately from modified ones so the link cannot make every run claim the tree moved.
- **`check-index-ids.py` still has no gate.** The entry point is now its only operator-reachable
  home; a suite gate would need `team-db` and a git object store, which is a separate decision.
- **A dead branch in `check-doc-citations.py` was left alone** and is recorded here: line
  `[n for n in nums if hits_any(...)] if False else [...]` names a function that does not exist. It
  is unreachable (`False`), so behaviour is right and it is not weakened by leaving it — but anyone
  who flips that flag gets a `NameError`, and "fixing" it silently would be a change this task did
  not measure.
